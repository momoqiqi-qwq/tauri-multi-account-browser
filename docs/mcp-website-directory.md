# 网站分组与账号导航页

版本：0.11.0。变更记录：`CHANGES_V31.md`。

## 需求确认

用户选择：按网站分组，组内放账号；采用参考图的左侧分类、右侧图标网格布局，而非跨网站共享身份标签或批量切换整套标签页。

## 使用方式

1. 启动应用进入网站导航；浏览页面时点击地址栏的“网站导航”返回。
2. 左侧选择 Chat01、Claude、GitHub 等网站，右侧只显示该网站的账号。
3. 点账号图标打开或复用对应标签页；“返回网页”回到当前账号。分类切换不关闭既有标签或清理登录会话。
4. 左上角“添加网站”可先建立空分类，填写名称与主页。相同域名再次保存会更新分类名称，不产生重复分类。
5. 在网站分类下点击“新建账号”，账号表单自动使用该网站主页，并选中“单独覆盖”。
6. 搜索支持昵称、备注、手动分组、自由标签和主页；切换网站会清空当前搜索。
7. “1 列 / 2 列”切换左侧网站布局。分类名称、空分类、列数及最近选中分类在当前安装中记忆。
8. 账号图块悬停或键盘聚焦后可使用编辑按钮。改变账号设置中的主页即可改变网站归属；原有分组、标签仍独立保留。
9. 空网站可移除；有账号的网站不会提供删除网站入口。编辑网站时改填其他域名会添加新分类，不会自动迁移账号。

## 分类规则与持久化边界

- 继承模式使用全局主页；自定义模式使用账号主页。
- 不使用 `last_url`，因此 OAuth、登录页和临时浏览其他域名不会让账号跳组。
- 忽略大小写、`www.` 和路径差异；`chat.openai.com` 显式视为 ChatGPT 的历史别名。
- 不对未知子域名猜测公共后缀；不同未知子域与非默认端口保持分开。
- 无效主页进入“待设置网站”，不丢弃账号；支持在账号设置中修正。
- 原有账号及登录数据仍在既有 Rust store/Profile 目录中。本次未修改账号 schema 或迁移账号数据。
- 导航偏好存放于 UI localStorage 的 `mab-site-directory-v1`；它不是账号标签字段，也不随现有账号导出文件迁移。清理 UI 本地存储会重置分类别名、空分类和布局偏好，但已有账号仍能按主页自动分类。
- 网址只接受不带用户名/密码的 HTTP(S) 地址；已保存偏好会校验、去重并容忍损坏条目。最多保存 200 个自定义网站。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `src/lib/siteDirectory.ts` | 网址归一化、网站分组、搜索、偏好反序列化 |
| `src/composables/useWebsiteDirectory.ts` | 当前分类、搜索、列数、自定义网站及持久化 |
| `src/components/WebsiteDirectory.vue` | 网站侧栏、账号网格、新建网站表单与图标缓存 |
| `src/website-directory.css` | 独立导航布局与主题样式 |
| `src/App.vue` | 入口、加载/错误/打开状态、与现有标签页和账号表单衔接 |
| `src/components/AddressBar.vue` | 网站导航入口 |
| `src/components/ProfileSettingsDialog.vue` | 仅新建时应用网站主页预填 |
| `scripts/test-site-directory.mjs` | 使用现有 TypeScript 依赖执行纯逻辑回归 |

导航页覆盖宿主浏览区，但底层浏览组件保持挂载，避免激活账号时拿到零尺寸原生边界。导航页持有现有 WebView 抑制引用；底层宿主控件同时设置 inert，防止键盘误入。导航内打开账号设置/诊断对话框时，使用既有引用计数机制，不提前释放导航页的抑制引用。
