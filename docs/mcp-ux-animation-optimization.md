# 代码与交互动画优化审查

版本：0.11.1。变更说明：`CHANGES_V32.md`。

## 审查范围

本轮重点检查账号目录、标签栏计时、侧栏图标更新，以及宿主 UI 动画与原生 WebView 边界同步的关系。不是全仓安全审计或 Rust 性能基准。项目已有未提交改动全部保留。

LSP 对 Vue 文件返回 plaintext / inconclusive，不能据此认定没有符号；本轮通过具体文件读取和文本定位确认实现。

## 建议与实施结果

| 建议 | 原因 | 本轮结果 |
| --- | --- | --- |
| 缓存目录展示和搜索索引 | 同一个账号在标题、图标、回退文字等绑定中反复解析主页；搜索每次都重复小写化字段 | 已实施。复用网站分组，Map 索引保存展示信息与规范化搜索字段，搜索变化不重新解析 URL |
| 标签栏时钟按需启停 | 原代码不论有无实时计时都创建每秒定时器，目录遮挡时仍运行 | 已实施。没有有效运行中计时、被目录遮挡、页面隐藏、休眠或卸载时停止；恢复时按 Date.now 校正，不累加丢失 tick |
| 用 Map/Set 替代标签栏嵌套查找 | openTabs 对每项调用 profiles.find；多处 includes 重复扫描 | 已实施。使用账号索引、已打开/休眠/固定集合，保留标签顺序和固定规则 |
| 避免每次图标返回复制整个缓存 | 批量加载图标会反复创建越来越大的对象 | 已实施。侧栏缓存就地更新；没有宣称消除组件全部重渲染 |
| 分类切换只做轻量内容层进入 | 瞬切缺少连续感，但长时间错峰会阻塞快速选账号 | 已实施。160ms 透明度与 4px 位移；只有网站对应网格重新挂载时播放，不随每个搜索键入反复重播 |
| 提供短促直接的操作反馈 | 点击账号后异步创建 WebView，只有禁用状态不够明确 | 已实施。120ms 图标悬停微移/按下缩放；打开中的单个账号显示 900ms 等待边框，配套可读状态文字；初始加载用静态占位，不让整个列表持续闪烁 |
| 记住各网站的浏览位置 | 在网站之间或网页与目录之间切换会丢失滚动上下文 | 已实施。会话内保存最多 50 个网站；搜索从顶部开始，清空搜索恢复原位置；滚动时不写 localStorage |
| 统一减少动态效果 | 原设置仅将动画时长设为零，系统偏好未统一覆盖 | 已实施。动画开关关闭或系统 prefers-reduced-motion 时禁用动画/过渡，并取消指定交互元素的悬停位移；等待文字、边框、焦点和真实计时仍有效 |
| 不动画化原生网页几何尺寸 | 侧栏宽度动画不断触发布局、ResizeObserver 和原生边界同步 | 已实施。侧栏尺寸立即更新；仅保留背景色过渡；目录下方不可见宿主装饰动画暂停 |

## 动画设计边界

- 不对原生账号网页做淡出/缩放，不延迟导航页抑制引用的释放，不改变现有 WebView show/hide 生命周期。
- 不使用逐账号错峰、整表 FLIP、持续骨架闪烁或 layout 高度/宽度插值。
- 入场动画只作用于宿主网格内容层，点击不需要等待动画结束。
- 关闭动画不会关闭 AI 对话实际时长计算。隐藏窗口是否触发 document.hidden 由平台决定；监听到 visibilitychange 后会正确启停。
- 状态明确性优先于动画：减少动态效果时也能看到“正在打开账号”或“正在创建并打开账号”。

## 文件组织

- `src/lib/siteDirectory.ts`：目录索引、标准化搜索字段。
- `src/composables/useWebsiteDirectory.ts`：缓存索引与筛选结果。
- `src/components/WebsiteDirectory.vue`、`src/website-directory.css`：展示复用、反馈、占位和进入动效。
- `src/composables/useDirectoryScroll.ts`、`src/lib/directoryScroll.ts`：滚动位置恢复和有界会话内存。
- `src/composables/useActivityClock.ts`、`src/components/TabStrip.vue`：可见性驱动的计时更新与账号索引。
- `src/components/ProfileSidebar.vue`：缓存就地赋值。
- `src/motion.css`：统一动画时长、系统偏好、应用开关及原生边界保护。
- `src/main.ts`、`src/style.css`、`src/App.vue`：样式入口、去除旧的零时长规则及传入目录遮挡状态。

## 后续建议（未实施）

1. **大型弹窗按需加载**：可减少首屏 JS，但需要同时处理首次打开的加载占位、失败重试和原生网页抑制，不能仅机械替换成动态 import。
2. **跨组件图标请求去重与有界缓存**：目录重新打开仍可能发起取图标 IPC；建议以账号及主页/代理配置为依据，配合失败重试 TTL，避免盲目按网站全局合并请求。后端已有本地缓存，本轮不改变隔离或代理语义。
3. **超大列表虚拟化**：已检查 300 个账号的滚动；数千个账号时可测量后再选择虚拟网格，不先引入复杂滚动和键盘定位逻辑。
4. **真正的 Windows 性能录制**：使用大量真实账号测量帧时间、长任务和原生边界 IPC 次数，再决定是否继续优化 Rust store 写入或后台状态刷新。
