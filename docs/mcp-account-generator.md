# 多账号生成器实现与验证

## 范围和版本

- 版本：0.13.0；变更说明：`CHANGES_V33.md`（生成器初版）、`CHANGES_V35.md`（全选 / 记忆选择 / 登录账号）。
- 用户确认采用「目标网站 × 已有账号配置」模式，不新增数量编号生成模式。
- 参考图仅作为功能启发，界面改为三个步骤，避免把网址、设置、来源和结果同时堆在一个表单中。
- 这是浏览器容器生成器，不负责注册网站账号，也不复制网站登录态。

## 使用路径

1. 在网站导航顶部点击「多账号生成器」；位于具体网站时预填该网站的配置主页，绝不使用登录跳转后的地址。
2. 或在「账号管理工具」顶部打开生成器。原有模板、编号批量创建、导入导出均保留。
3. 第一步填写网址，每行一项，支持 `网站名称 | https://example.com/`。可以设置公共前缀、命名顺序；分隔符、统一分组和标签继承放在默认收起的详细设置中。
4. 第二步搜索并勾选来源账号。搜索不清除已选项；「全选」选中全部来源账号（不受当前搜索影响），「选中搜索结果」只在有搜索词时出现、仅增加当前筛选结果，「清空选择」清除全部已选项。行内会显示该账号最近识别到的登录账号（优先邮箱），同名账号据此区分。
5. 第二步的选择会被记住：关闭弹窗或重启应用后再次打开，仍沿用上一次的勾选，但记忆里已删除的账号会被自动丢弃，不会带出「来源账号已删除」的错误。
6. 第三步按每页 10 项预览名称、来源、网址和处理结果，确认数量后生成。
7. 成功后展示本次创建的账号；可以关闭弹窗，或查看网站导航中的全部账号。不会自动打开新网页。

## 布局

- 桌面弹窗最大宽度 1120px；固定头部、步骤条和操作栏，内容区独立滚动。
- 主要填写/预览区与 246px 摘要区分开，字段上方放标签、下方放短说明。
- 来源账号采用可整行点击的复选行，不在行内暴露完整代理地址或凭据。
- 行内登录账号来自各账号容器被动上报的状态（`get_profile_statuses` 的 `email`，取不到时退回 `account`），没打开过的账号不显示占位；它不是新抓取，也不是实时校验。
- 窄窗口切换为单栏，并保留精简数量摘要；极窄的结果表允许内部横向滚动，不撑开整个弹窗。
- 沿用现有主题变量；未增加背景计时器、几何过渡或逐项入场动画。
- 步骤切换重置主区域滚动并将键盘焦点移入当前内容，结果换页重置表格滚动。

## 生成和重复项规则

### 输入及数量

- 仅允许不含用户名/密码的 HTTP(S) 目标网址；省略协议时补 HTTPS。
- 完整 URL 规范化后完全一致的输入只保留第一项和其名称。
- 路径、查询参数和片段均参与 URL 比较；这与网站导航按网站域名归类是两套不同规则。
- 单次最多 200 个组合，即「不同目标 URL 数 × 不同来源 ID 数」不超过 200。即使跳过后少于 200，也不能用超限组合绕过前端限制。
- 单个来源不允许因重复选中而生成两次；来源被删除时阻止整批提交，不静默丢掉该来源。
- 生成名称最多 80 个 Unicode 字符；超限明确报错，不静默截断。

### 配置白名单

新主页明确设置为目标网址，`url_mode` 为 `custom`。复制来源的：

- `incognito`、`proxy`、`user_agent`、`timezone`、`locale`、`fingerprint_guard`。
- 分组默认沿用来源，填写统一分组时覆盖新账号的分组。
- 标签默认复制，支持关闭，并复制数组而非共享引用。

不传递来源 ID、Cookie、网站存储、浏览历史、`last_url`、创建/使用时间、收藏、备注和头像。新 ID 由现有 Rust 创建流程生成，不调用克隆用户数据目录的逻辑。临时账号模式也会沿用；不同新容器可能使用相同代理出口，不能据此宣称获得不同 IP 或网站身份。

### 重复判断

- 默认按「名称去除首尾空白后精确匹配 + 规范化完整主页 URL 相同」跳过已有账号。名称大小写不同视为不同名称。
- 继承主页的已有账号按宿主当前全局默认主页参与比较，不看 `last_url`。
- 不同来源昵称相同时，先在本批组合内确定性追加 `(2)` 等序号，不能因为昵称相同而丢掉另一个来源。
- 关闭跳过时，对已占用的同名同主页组合追加序号，仍然不覆盖任何已有账号。
- 没有持久化来源关系 ID。修改命名、网址或来源后可能产生新组合；「跳过」不等于识别任意历史复制关系。

## 提交与状态保护

- `src/lib/accountGenerator.ts` 为纯解析和计划函数，不执行写入。
- `src/composables/useAccountGenerator.ts` 在点击生成后重新调用 `list_profiles`，用最新资料重建计划；新配置、删除项或重复项导致计划变化时，要求再次确认。
- 刷新得到的账号同步回宿主列表；成功创建的回传结果立即按新 ID 合并，不把后续刷新失败误报成创建失败。
- 整批使用一次既有 `create_profiles_bulk` 调用。`src-tauri/src/profiles.rs` 先校验全部草稿再统一保存，后端原有 200 条限制未改动。未新增 Rust 命令、数据结构或迁移。
- 生成期间禁用关闭、步骤切换和重复提交。命令未确认成功时要求先重新检查账号列表，避免直接盲目重试；不擅自承诺失败时一定没有写入。
- 前端检查不是跨进程事务性唯一约束，检查与保存之间的外部并发修改仍可能形成重复项。后端没有新增请求幂等键；跨进程强去重不在本次范围。
- 弹窗保持常驻组件以满足 `useDialogSuppression` 的首次打开生命周期。工具弹窗移交时先获取生成器的抑制引用，再关闭原弹窗；切回网站导航时先挂载导航，再释放生成器引用。
