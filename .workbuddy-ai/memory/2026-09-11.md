## 关键环境解法（重要，可复用）

Git Bash 的 `/usr/bin/link.exe`（GNU hardlink 工具）会**遮蔽 MSVC 链接器**，导致 `tauri-build` 构建脚本报
`link.exe returned an unexpected error` / `LNK1181: 无法打开输入文件"kernel32.lib"`。

解法见 `scripts/cargo-msvc.sh`：
1. 把 `MSVC\...\bin\Hostx64\x64` 前置到 PATH，让 `link.exe` 解析到 MSVC 版本；
2. `INCLUDE` / `LIB` / `LIBPATH` 必须用 **Windows 反斜杠绝对路径**（bash 里反斜杠需转义或用单引号），传 POSIX 路径无效；
3. 用 bash 脚本封装环境，避免在 Bash 工具里多次 `export` 被引号处理破坏。

组件路径：VS 18 Community / MSVC 14.50.35717 / SDK 10.0.26100.0。

### 解决 Windows 测试二进制 0xc0000139
根因：`tauri` 的 `test` feature 链入 tray-icon/muda → `comctl32.dll!TaskDialogIndirect`，
只在 Common-Controls **v6**（WinSxS）里存在；`System32\comctl32.dll` 是 v5.82 不导出它。
正式 app 由 tauri-build 注入 manifest，测试 harness 没有 → 加载失败。

三个死胡同（已验证无效）：`build.rs` 拿不到 `CARGO_CFG_TEST`；
`cargo:rustc-link-arg-tests` 不覆盖 `--lib` harness；
无作用域 `rustc-link-arg` 会让 app 出现 CVT1100 资源重复。

最终方案：静态 manifest 文件 `src-tauri/common-controls.manifest` +
`scripts/cargo-test.sh` 用 `cargo --config ...rustflags=[...]` 只在测试时注入。
`mt.exe`（Windows SDK）也必须在 PATH，已加进 `cargo-msvc.sh`。

另发现 store 在 mock app 间**进程内共享**，测试会互相污染；
