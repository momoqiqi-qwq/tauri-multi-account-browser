## v24 三项需求（AI 使用时间 / 自动刷新）

用户提的三条：
1. 自动刷新只在 AI 正在回答时刷新，AI 不回答不刷新。
2. 侧边卡片显示的时间要是 **AI 使用时间**，不是打开标签的时间（原网页本来就有这功能）。
3. 标签页的显示时间也改成 AI 使用时间。

落地：
- `status.rs::save_profile_status` 记录 `answer_finished_at`（RFC3339）并持久化。
- `StatusSidebar.vue` prop `showUpdatedTime` → `showAiUsageTime`，渲染
  `{{ 时间 }} AI使用`，只在该账号**真的用过 AI** 时才显示。
- `App.vue` 自动刷新条件翻转：`if (!statuses.value[id]?.answer_generating) return`。
- 偏好字段 `showStatusUpdatedTime` → `showAiUsageTime`，`uiPreferences.ts` 保留旧键读兼容；
  同时删掉 `pauseAutoRefreshWhileGenerating`（自动刷新语义已整体改变，这个开关没意义了）。

## v24 自查抓到的真 bug（重要）

第一版用 `answer_ready` **上升沿**判断「AI 答完了」。回头读 `webviews.rs` 的扫描脚本才发现：
```js
answerReady = !profileActive;   // 只有后台账号才翻 true
```
注释写明是为了不对当前正在看的账号弹「回答完成」提醒。**后果：用户正在看的那个账号
`answer_ready` 永远不翻 true，AI 使用时间永远不更新** —— 恰好是需求 3 的主场景。

修法：改用 `answer_generating` **下降沿**（generating: true → false）。
`clear_profile_answer_ready` 相应改成只清 `answer_ready`、**保留** `answer_finished_at`
（它现在是「最近一次 AI 完成回答的时间」，与未读提醒解耦，要持久展示）。

教训：**改状态机前先读产生这个状态的注入脚本**，别只看字段名想当然。

## 测试基建隔离 bug

新增 5 个 status 单测后挂了 2 条（`is_none()` 断言失败）。根因不是被测代码，是
`reset_store()` **没删 `STATUS_KEY`**，而 tauri-plugin-store 按文件路径进程内共享 store，
前一个用例写的 status 串到了后一个。补 `store.delete(STATUS_KEY)` 后 48 全过。
→ 以后给 store 加新 key，第一件事是去 `reset_store()` 补上对应 `delete`。
