### 坑：本地 remote-tracking ref 会被删
推送/抓取都成功，但 `.git/refs/remotes/origin/` 目录会**莫名消失**，
导致 `git branch -vv` 显示 `[gone]`、`git rev-parse origin/master` 报 unknown revision。
`git fetch` 与 `git update-ref` 都返回 0 但写不进去。
**解法**：手动写 ref 文件后执行 `git pack-refs --all`，写进 `packed-refs` 就不会再丢：
```
mkdir -p .git/refs/remotes/origin
printf '%s\n' <sha> > .git/refs/remotes/origin/master
git pack-refs --all
```

## V25：点图片不再顶掉账号页，改成独立预览小窗

用户原话：「点击上传的图片不要自动切换我的账号的网址，你应该用一个小窗口出来
把我打开的图片的路径弄到这个小窗头上然后显示出这个图片」。

### 根因
账号页注入的 `NEW_WINDOW_PATCH_JS` 为了保住下载，会把 `target=_blank` 摘掉
（`el.removeAttribute('target')`）。而站点里的图片就是
`<a target="_blank" href=".../x.png"><img></a>` —— 摘掉 target 后图片就地整页导航，
账号页网址变成图片地址，聊天会话全丢。`window.open(图片地址)` 那条更直接：
`.png` 命中 `isDownloadLike`，补丁主动 `location.href = url` 整页导航。

### 方案
沿用 `mbstatus://` 的假导航套路：点图片 → `preventDefault` →
`location.href = 'mbimage://open?u=…&t=…'` → 宿主 `on_navigation` 拦下 `return false`
（账号页一动不动）→ `run_on_main_thread` 下一拍建 `WebviewWindow`
（760×620、居中、标题 = 百分号解码后的图片路径），注入 `IMAGE_PREVIEW_JS` 把
WebView2 生成的裸图片文档改造成「顶部路径栏（可复制）+ 图片本体 + 适应/原始大小」。

### 三个坑（都写进了 MEMORY.md）
1. **合成点击**：默认 `ai_exts` 白名单含 png/jpg/jpeg/webp，自动下载脚本是
   `el.click()` 触发锚点的 —— 拦截器若不加 `if (!e.isTrusted) return`，
   「AI 文件自动下载」会被整条打断且满屏弹窗。
2. `Url::path()` **不解码**百分号 → 标题栏里中文文件名是 `%E5%9B%BE…`，
   自己写了 `percent_decode()`（不新增依赖，非法序列原样保留，不 panic）。
3. 相对路径图片链接（`/files/x.png`）要先 `new URL(href, location.href)` 再看扩展名，
   直接对 `getAttribute('href')` 判扩展名会漏。

### 取舍
识别口径只认 `blob:` + 常见图片扩展名，**没有**用「a 里包 img 就当图片」的宽口径 ——
卡片式列表的缩略图也是这个结构，宽口径会把「点缩略图进详情页」也变成弹小窗。
`download` 属性优先（明确下载意图不拦）。无扩展名的图片直链（`/abc123`）仍会走老路。

### 数据目录
预览窗优先复用账号自己的 UserDataFolder（blob: 和需要 cookie 的图片只有同分区取得出来），
WebView2 不允许同目录挂不同环境参数，失败就换 label 退默认目录再建一次。
